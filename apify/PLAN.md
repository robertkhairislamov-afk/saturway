# План: пассивный доход через Apify Store

## Цель

Стабильно получать не меньше $100 в месяц чистыми без ручной работы с клиентами.

## Что уже решено

- **Saturway отложен.** Шанс заработать на нём оценён меньше чем в 1%. Бэкенд не запускается: 45 ошибок TypeScript, Zod-схемы переданы в Fastify без type provider. Фронтенд — макет без API.
- **Рынок России исключён.**
- **Модель — портфель примерно из 10 акторов в Apify Store** с оплатой за события (pay-per-event).
  - Apify платит 80% выручки минус стоимость запусков.
  - Выплаты раз в месяц: на PayPal от $20, на банковский счёт от $100.
  - Чтобы получать $100 чистыми, нужно около $150 выручки в месяц на все акторы вместе.
- **Логика вероятностей.** Шанс, что хотя бы один актор принесёт $100 в месяц, равен 1 − (1 − p)ⁿ.
  - При p ≈ 8% и 10 акторах это около 57%.
  - Хороший выбор ниш поднимает p до 10–12%, и шанс вырастает до 65–72%.
- **Инструмент поиска ниш — внутренний, не продаём.** В Store уже есть минимум шесть аналогов, например `johnvc/store-actor-intelligence-api` и `groundworklabs/apify-opportunity-finder`.

## Анализ ниш — сделан

Результаты — в [NICHES.md](NICHES.md), скрипты — в `niche-finder/`. Главное:

- $100 в месяц — это примерно 40 пользователей в месяц на все акторы вместе, при средней выплате около $2,5 за пользователя.
- По данным магазина, из разработчиков с 10–19 акторами до этого уровня доходит около половины, с одним актором — 5%.
- Первые 10 акторов: Google News, Google Play, Greenhouse, Workday, Lever, Ashby, Dice, Welcome to the Jungle, Rightmove, Home Depot.

- Цена: $0.001 за вакансию (`apify-default-dataset-item`), без платы за старт. Задана через API 24.09.2026.
- Название, описание, категории (JOBS, LEAD_GENERATION, AUTOMATION), SEO и память 512 МБ заданы через API. Действующая сборка 0.1.4.

Что умеют:

1. **Единый формат** для всех четырёх систем: должность, отдел, команда, все локации, удалёнка, тип занятости, зарплата `{min, max, currency, interval, source}`, описание текстом и HTML, ссылки на вакансию и отклик, даты.
2. **Зарплаты.**
   - Из данных самой системы: у Greenhouse — через `pay_transparency`, у Lever — `salaryRange`, у Ashby — compensation.
   - Из текста описания: например, «168,000 USD - 264,500 USD». Проверено на реальных данных, ложных срабатываний на суммах вроде «рынок $100B» нет.
   - Результаты: у NVIDIA зарплата найдена во всех вакансиях в США, у Airbnb — в 134 вакансиях из 160.
3. **Workday больше 2000.** Поиск Workday отдаёт максимум 2000 вакансий. Актор делит поиск по фильтрам самого сайта, например по категориям, и собирает всё: у NVIDIA 2655 вакансий. Страницы результатов грузятся параллельно.
4. **Фильтры:**
   - ключевые слова в названии, с производными формами (engineer → Engineering) и `*`;
   - исключения, локации, только удалённые, отдел, дата публикации, только с зарплатой.
   - У Workday ключевые слова ищутся и на самом сайте.
5. **«Только новые с прошлого запуска».** Виденные вакансии хранятся в именованном хранилище пользователя отдельно для каждой задачи и компании. Карточки Workday загружаются только для новых вакансий.
6. **Ввод:** названия, любые ссылки на доски, для Workday — ссылка на страницу поиска вместе с выбранными на сайте фильтрами.

Как обновить акторы:

1. `cd actors/ats-jobs && npm test`.
2. `node scripts/build.mjs --out /tmp/ats-actors` — собирать вне репозитория, иначе `apify push` пропускает файлы из `.gitignore`.
3. `cd /tmp/ats-actors/<ats> && apify push`.

Идеи на потом:

- Режим «поиск по всем компаниям» со встроенным списком досок. Так работают лидеры ниши fantastic-jobs: они ищут вакансии сразу по всем компаниям, а не по списку.
- Отдел для Workday через фильтр «Job Category» сайта.

Теперь в портфеле 5 акторов. По данным магазина, до $100 в месяц доходят около 39% разработчиков с 5–9 акторами (верхняя граница), против ~5% с одним.

Что умеет:

Технически:

Проверка на платформе, сборка 0.1.3:

- пустой ввод — 50 приложений с карточками за 4–18 секунд;
- пример из формы — 80 приложений за 22 секунды;

- Стажировки и обучение с работой (alternance, apprenticeship) теперь разделены в `employmentType` для всех акторов на общей основе.

### 8b. LinkedIn Jobs Scraper — опубликован 28.09

Двенадцатый актор с вакансиями: `robertosan16/linkedin-jobs-scraper` (ID `kR8Ia5qeHhFSHGI9t`), код `src/adapters/linkedin.js`. Цена $0.50 за 1000, без платы за старт.

Решение владельца 27.09: делать, несмотря на запрет парсинга в соглашении LinkedIn. Поэтому:
- только публичные страницы для гостей, без входа и cookies;
- никаких данных о людях: авторы вакансий, рекрутеры и сотрудники не читаются;
- в README пометка, что актор не связан с LinkedIn.

Как устроено:
- Поиск: `linkedin.com/jobs-guest/jobs/api/seeMoreJobPostings/search`, 10 вакансий на страницу, `start` до 990 (дальше 400). Страница вакансии: `/jobs-guest/jobs/api/jobPosting/<id>`. Из неё берутся описание, уровень, тип занятости, функция, отрасли, число откликов и Easy Apply.
- Что гостевой поиск делает на 27.09 (проверено сравнением выдачи):
  - применяет `keywords`, `location`, `distance`, дату (`f_TPR`), Easy Apply (`f_AL`) и компанию (`f_C`);
  - требует `location`, без неё отвечает 429 (поэтому по умолчанию `Worldwide`);
  - игнорирует удалёнку (`f_WT`), тип занятости (`f_JT`), опыт (`f_E`) и сортировку (`sortBy`).

- Прокси. В общем HTTP-клиенте есть ротация (`rotate`):
  - сессия обслуживает до 5 запросов подряд и меняется при 429, 999 или пустой странице;
  - проверка `accept` отличает настоящую страницу от пустой или страницы входа, такая страница повторяется с другого адреса;
  - если в вводе прокси нет, на платформе берутся резидентные прокси Apify (`rotatingProxy`), локально запросы идут напрямую.
- Если страница вакансии так и не открылась, вакансия сохраняется с данными из поиска.

### Кейс: продажи в Южной Австралии со спонсорством визы, 15.10

Задача: руководителю продаж из-за рубежа нужна работа в Аделаиде или Южной Австралии с работодателем, который спонсирует визу. Данные кандидата хранятся только в scratchpad, в репозиторий не попадают; кейс публикуем только обезличенным и с согласия кандидата.

- **Сбор.** Два запуска All-in-One, `location: South Australia`, сайты SEEK, Indeed, Glassdoor, LinkedIn:
  - 14 должностей — 5286 вакансий за 25 минут, $0.74 платформы;
  - 7 запросов о спонсорстве («Sales Manager visa sponsorship», «482 sponsorship sales»…) — 298 вакансий за 40 секунд, $0.003.
  Сырые наборы сохранены как именованные: `sa-jobs-raw-titles-2026-10-15`, `sa-jobs-raw-sponsorship-2026-10-15`. Обработанный набор — отдельно: `sa-jobs-processed-2026-10-15`. Акторы не менялись: вся логика — обработка поверх их вывода (скрипт в scratchpad).
- **Обработка:**
  - **Удаление дублей:** компания + должность + город. Вторым проходом склеивается одна вакансия, найденная на разных сайтах под другим именем или в другом городе: тот же заголовок и то же начало текста. С одного сайта не склеивается: это разные места, например по одному на магазин.
  - **Спонсорство.** Сначала ищутся запреты, затем YES / POSSIBLE / NO / UNKNOWN:
    - у каждого YES и NO — точная цитата из объявления;
    - «спонсорство после испытательного срока / для лучших сотрудников / только тем, кто уже в Австралии» — это POSSIBLE, не YES;
    - слово «sponsor» само по себе не считается («manage sponsorships»), «citizenship is not required» не считается запретом;
    - все 38 фраз из постановки задачи распознаются верно.
  - **Баллы 0–100** по весам задачи. NO — не выше LOW PRIORITY, должности вне продаж, BD и маркетинга — не выше 39.
  - **Дополнительные штрафы:**
    - объявлениям старше 90 дней;
    - «commercial manager» в стройке, где это договоры и сметы, а не продажи.
  - **Отброшены объявления не из Австралии:** у Indeed «SA» бывает Саудовской Аравией, LinkedIn ставит часть иностранных объявлений в «Senior, South Australia».
- **Итог:**
  - 5584 найдено, 3347 уникальных;
  - продажи, BD и маркетинг — 755 (в SA — 744);
  - из них YES 0, POSSIBLE 77, NO 66, UNKNOWN 612;
  - YES по всем профессиям — 9: врачи, повара, менеджер магазина, через DAMA;
  - STRONG MATCH 3, APPLY 49.
  - Вывод для кейса: явного спонсорства в продажах в Аделаиде сейчас нет. Шанс — у крупных международных компаний (POSSIBLE) и в прямом вопросе работодателю. Чат-бот такой подсчёт по 5 тысячам объявлений с цитатами не делает.
- **Идея продукта:** отдельный актор «Visa Sponsorship Jobs» (Австралия, потом Великобритания и Канада) поверх All-in-One со статусом спонсорства, цитатами и баллами. Решать после отзыва кандидата.
