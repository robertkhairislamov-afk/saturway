# План: пассивный доход через Apify Store

## Цель

Стабильно получать не меньше $100 в месяц чистыми без ручной работы с клиентами.

## Что уже решено

- **Saturway отложен.** Шанс заработать на нём оценён меньше чем в 1%. Бэкенд не запускается: 45 ошибок TypeScript, Zod-схемы переданы в Fastify без type provider. Фронтенд — макет без API.
- **Рынок России исключён.**
- **Модель — портфель примерно из 10 акторов в Apify Store** с оплатой за события (pay-per-event).
  - Apify платит 80% выручки минус стоимость запусков.
  - Выплаты раз в месяц: на PayPal от $20, на банковский счёт от $100.
  - Чтобы получать $100 чистыми, нужно около $150 выручки в месяц на все акторы вместе.
- **Логика вероятностей.** Шанс, что хотя бы один актор принесёт $100 в месяц, равен 1 − (1 − p)ⁿ.
  - При p ≈ 8% и 10 акторах это около 57%.
  - Хороший выбор ниш поднимает p до 10–12%, и шанс вырастает до 65–72%.
- **Инструмент поиска ниш — внутренний, не продаём.** В Store уже есть минимум шесть аналогов, например `johnvc/store-actor-intelligence-api` и `groundworklabs/apify-opportunity-finder`.

## Анализ ниш — сделан

Результаты — в [NICHES.md](NICHES.md), скрипты — в `niche-finder/`. Главное:

- $100 в месяц — это примерно 40 пользователей в месяц на все акторы вместе, при средней выплате около $2,5 за пользователя.
- По данным магазина, из разработчиков с 10–19 акторами до этого уровня доходит около половины, с одним актором — 5%.
- Первые 10 акторов: Google News, Google Play, Greenhouse, Workday, Lever, Ashby, Dice, Welcome to the Jungle, Rightmove, Home Depot.

Код лежит в `actors/google-news/`. Прошли 11 тестов и живые запуски: поиск, темы, топ-новости, немецкое издание, диапазон дат по дням, лимиты, расшифровка ссылок на издания.

На Apify: актор `robertosan16/google-news-scraper` (ID `pyiyAg3vjflJK3zZC`), сборка 0.1.1.

- Пробный запуск с Apify Proxy: 60 статей, расшифрованы 60 ссылок из 60, 83 секунды, расход $0.0009.
- Название, описание, категории (NEWS, MARKETING, AI) и SEO заданы через API.
- Платёжные данные для выплат заполнены: компания и PayPal.
- Цены заданы через API 24.09.2026: $0.002 за статью (`apify-default-dataset-item`), $0.001 за расшифрованную ссылку (`url-resolved`), без платы за старт.
- Опубликован в Store 24.09.2026: https://apify.com/robertosan16/google-news-scraper. Действующая сборка 0.1.3: при пустом вводе запускается пример поиска, чтобы проходил ежедневный автотест Apify.

Как опубликовать:

1. Выложить в Apify. Два способа:
   - через API с токеном из API credentials окружения: создать актор из `actors/google-news` и собрать;
   - через Apify Console: Link Git repository → ветка `claude/gifted-dirac-sv0ed6`, папка `apify/actors/google-news`.
2. Проверить запуск на платформе с Apify Proxy.
3. В Console в разделе Monetization выбрать pay-per-event:
   - `apify-default-dataset-item` — $0.002 за статью;
   - `url-resolved` — $0.001 за расшифрованную ссылку;
   - без платы за старт.
4. Указать PayPal для выплат и опубликовать в Store.

### 2. Следующий шаг — семейство акторов с вакансиями (Greenhouse, Lever, Ashby, Workday)

Почему раньше Google Play: четыре актора на одной общей основе кода обходятся почти как один, а официальные публичные API стабильны, почти не требуют поддержки и не содержат персональных данных. Google Play переносим на потом: спрос там в основном на отзывы, где идёт ценовая война по $0.0001 за отзыв и есть имена авторов.

Конкуренты (пользователи за 30 дней, цена за вакансию):

- Greenhouse: fantastic-jobs — 123, $0.002; bovi — G/L/A вместе, 102, $0.0015; jobo.world — $0.004.
- Lever: fantastic-jobs — $0.0025.
- Ashby: fantastic-jobs — 69, $0.002; jobo.world — $0.00099.
- Workday: fantastic-jobs — 133, $0.002; johnvc — $0.001 + старт.
- Универсальные на много ATS: memo23 — 116 ATS, $0.004; webdata_labs — $0.001.

Чем выделимся:

1. **Цена.** $0.001 за вакансию, вдвое дешевле fantastic-jobs.
2. **Режим «только новые с прошлого запуска».** Удобно для регулярного мониторинга и даёт повторные запуски.
3. **Единый формат для всех ATS.** Зарплата, где она есть (Ashby compensation, Lever salaryRange), описание текстом и HTML, ссылка на отклик, даты.
4. **Фильтры.** Ключевые слова, локация, удалёнка, отдел, дата публикации.
5. **Удобный ввод.** Принимаются названия компаний, ссылки на страницы карьеры или слаги.

Этапы:

1. Общая библиотека: ввод, фильтры, дедупликация, единая схема, режим «только новые».
2. Адаптеры Greenhouse, Lever и Ashby — простые JSON API.
3. Адаптер Workday: POST `/wday/cxs/{tenant}/{site}/jobs` с постраничной выдачей и карточка вакансии.
4. Тесты на сохранённых ответах, живые запуски.
5. Четыре отдельных актора в Store, у каждого своя страница для SEO. Цены через API, публикация — кнопкой владельца.

API проверены 24.09.2026: Greenhouse, Lever, Ashby (с compensation) и Workday (NVIDIA, 2000 вакансий) отвечают без ключей.

После этого в портфеле будет 5 акторов. По данным магазина, до $100 в месяц доходят около 39% разработчиков с 5–9 акторами (верхняя граница), против ~5% с одним.

## Как был сделан анализ (для пересчёта)

1. Собрать данные через публичный Store API без токена:
   `GET https://api.apify.com/v2/store?limit=1000&offset=N` с постраничным обходом.
   Нужные поля: `title`, `name`, `username`, `categories`, `stats.totalUsers`, `stats.totalUsers7Days`, `stats.totalUsers30Days`, `stats.totalUsers90Days`, `stats.lastRunStartedAt`, `currentPricingInfo`. Перед написанием кода проверить реальный формат ответа.
2. Сгруппировать акторы по целевому сайту или платформе, определяя их по `title` и `name`.
3. Оценить каждую нишу: оценка = спрос × слабость конкурентов × простота сбора данных.
   - Спрос — сумма `totalUsers30Days` по группе.
   - Слабость конкурентов — мало акторов, у лидера небольшая доля, лидеры давно не обновлялись или плохо оценены.
   - Простота сбора — насколько сайт защищается от парсинга. Оценить вручную для лучших кандидатов.
4. Выдать топ-10 ниш с обоснованием.

## После анализа

- Собирать и публиковать по актору каждые 1–2 дня: JS/TS, Crawlee, Apify SDK.
- Брать только публичные данные без персональной информации и соблюдать правила сайтов.
- Через 4–6 недель пересмотреть портфель:
  - есть пользователи, но нет денег — менять цену;
  - нет пользователей — менять нишу или карточку актора.
  - Слабые акторы снимать, сильные улучшать.
